# 评委答辩问答

## 1. 苏品智航解决什么问题？

苏品智航帮助江苏制造企业把企业资料、商品信息、公开市场数据、海外竞品样本、内容趋势和 AI 分析整合成一个出海选品流程。它降低建档、市场预研、营销草稿和报告制作成本，适合比赛演示和企业初步决策。

## 2. 它为什么是智能体应用？

系统不是单次问答，而是把企业建档、商品导入、数据源聚合、目标市场选择、竞品样本、内容趋势、机会评分、营销生成、报告输出和聊天审阅组织为连续工作流。每一步都有输入、输出、来源说明、状态记录和 fallback 处理。

## 3. Qwen 用在哪里？

Qwen 用于企业照片理解、商品多图理解、产品关键词补全、评分解释、营销内容生成、报告草稿生成和聊天解释报告。所有第三方 Key 只由后端读取，前端不接触密钥。

## 4. 为什么要支持拍照新增企业？

很多中小制造企业资料不完整，现场只有门头、展台、名片、产品目录或宣传页。拍照新增企业可以先生成企业草稿，提取企业名称、地区、行业、主营产品和目标市场建议，再由用户确认入库。这样既降低录入成本，也保留人工复核。

## 5. 多图商品识别为什么比单图更可靠？

单图通常只覆盖主图或标题，容易漏掉规格、材质、尺寸、包装、使用场景和卖点。多图可以把主图、参数图、详情页和场景图合并成证据集合，互相校验字段一致性，并给出每个字段的 evidence 和置信度。系统仍然不把多图识别当成最终事实，低置信度字段必须由用户修改或确认。

## 6. 如果 AI 识别错了怎么办？

识别结果先进入草稿，不直接写入正式企业或产品库。用户可以修改字段、删除错误证据、补全缺失信息，或者拒绝草稿。只有点击确认后，系统才保存正式记录。报告和分析使用的是确认后的记录，而不是未确认的 AI 输出。

## 7. 为什么不直接爬淘宝、京东、拼多多？

我们不做批量采集，不绕过登录、验证码、风控、签名校验或 App 私有接口。系统只处理用户主动提供的单个链接或截图；链接解析只尝试公开可访问页面的基础信息。遇到限制时，系统会提示上传截图继续分析。

## 8. 如果链接解析失败怎么办？

系统返回 `needs_screenshot`，前端提示“请上传商品截图继续分析”。这不是流程中断，而是合规兜底：不使用 Cookie、登录态、验证码识别、代理池或模拟登录。截图导入仍然可以完成商品草稿、人工确认和后续分析。

## 9. 用户上传截图是否合规？

系统只接收用户主动上传的图片，并在前端提示裁剪订单号、手机号、地址、聊天记录、证件号码和账号头像等隐私信息。后端限制文件类型和大小，保存到运行时目录，不提交 GitHub。识别结果只保留业务相关字段和最小证据摘录。

## 10. 国内商品价格能不能作为海外售价？

不能。国内截图或链接中的价格只作为产品信息完整度参考，不代表海外售价、成交价、采购成本或利润判断。海外价格判断仍基于海外竞品样本、目标市场数据和人工复核。

## 11. 五大洲目标国家扩展后如何保证速度？

系统通过三层方式保证速度：第一，后端维护目标国家目录和默认演示组合，避免每次现场临时配置；第二，数据源服务有缓存、超时和 fallback，外部 API 慢或失败时不阻塞主流程；第三，`DATA_COLLECTION_CONCURRENCY` 控制并发，比赛现场建议使用 6 个国家覆盖五大洲，而不是一次性跑满所有国家。

## 12. 外部 API 不可用时怎么办？

World Bank、GDELT、YouTube、Etsy、UN Comtrade 等数据源都有缓存或 CSV fallback。比赛现场即使没有 Key、额度不足或网络异常，也可以完成企业、产品、分析、看板、营销和报告主流程。报告会标注 fallback 状态，避免把兜底样本说成实时外部结果。

## 13. 数据源是否等于官方结论？

不是。公开 API、公开页面基础信息、海外竞品样本和 CSV fallback 都是方向性证据。系统强调来源、时间、fallback 状态和人工复核，不把结果说成平台官方验证、法律意见或确定性经营结论。

## 14. 如何防止 AI 编造销量、认证或平台结论？

Prompt 和报告生成规则要求只使用结构化输入和证据字段，不得编造销量、评价、认证、排名或平台官方验证。报告会补充来源边界和风险提示，把结论定义为预研判断。低证据结论会被放进风险复核或下一步行动，而不是当成事实。

## 15. 全局聊天如何解释报告？

聊天读取当前页面的脱敏上下文，例如企业、产品、分析结果、报告版本和来源摘要。它可以回答“为什么推荐这个市场”“哪些数据来自 fallback”“哪些字段需要人工确认”，并把回答落回报告结构和来源边界。

## 16. 聊天如何防止误改报告？

聊天不会直接覆盖报告。修改请求先生成 `report_edit_proposals`，页面展示建议范围、替换内容和风险提示。只有用户点击应用，后端才创建新的 `report_versions` 记录并更新当前版本；点击拒绝只更新 proposal 状态。原版本始终保留，可查看和恢复。

## 17. 报告适合什么场景？

报告适合比赛演示、企业内部预研、选品讨论、海外市场初筛和行动计划对齐。正式投入前仍需核验认证要求、物流成本、关税政策、渠道规则、样品反馈和本地合规要求。

## 18. 如何保护 API Key？

所有 Key 只写入服务器 `.env` 或部署密钥配置，并只由后端读取。前端只能看到“configured/not configured”等状态，不显示明文、掩码、长度或哈希。日志、截图、报告、异常和聊天上下文中不得出现 Key、Token、Cookie 或 Authorization 头。

## 19. eBay、Rakuten、Reddit 是否已经接入？

它们是 P2 future provider，不作为当前 MVP 的真实 runtime 能力。演示和报告中不会把它们描述为本次真实调用来源。

## 20. 当前 MVP 不包含什么？

当前 MVP 不包含支付、订单、库存、物流、CRM、PDF 完整导出、批量商品采集、店铺采集、搜索结果采集、保证所有外部 API 实时可用，或对法律、关税、财务结果作确定性判断。
